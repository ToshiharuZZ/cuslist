# 🚀 Gemini Agentic Workflow System (GAWS) テンプレート

このディレクトリには、プロジェクト「cuslist」で確立された、高効率・高品質なAIエージェント開発ワークフローのテンプレート一式が含まれています。

新規プロジェクトを開始する際、これらのファイルをコピーしてカスタマイズすることで、初日から高度に組織化された開発体制を構築できます。

## 💎 コア・コンセプト

このシステムは以下の3つの柱で構成されています。

### 1. 影響分析ファースト (Impact Analysis First)
新機能追加や修正を行う前に、必ず **Impact Analysis Agent** が影響範囲を分析します。
- 手戻りの防止
- ドキュメントと実装の乖離防止
- リスクの早期発見
- **エージェント割当の最適化**（新規作成 vs 既存活用）

### 2. 厳格な品質保証 (Strict QA Gate)
**Reviewer Agent** の承認（APPROVED）がなければ、コードはメインブランチにマージされません。
- Manager Agentもこのルールに従います
- セキュリティと品質の担保

### 3. 自律的な状況報告 (Autonomous Reporting)
各エージェントは作業完了後、**自律的に**プロジェクト状況一覧（`project_status.md`）を更新します。
- Manager Agentによるマイクロマネジメントの排除
- リアルタイムな状況把握

---

## 🛠 導入手順

1. **ファイル配置**: 
   プロジェクトの `docs/agents/` 配下に `00`〜`03` のファイルをコピーし、名前を適切に変更します（例: `manager_agent.md`）。

2. **ダッシュボード作成**:
   `04_project_status.md` をコピーして `docs/project_status.md` を作成します。

3. **開発エージェントの定義**:
   `03_domain_agent.md` を元に、必要なドメインエージェント（例: `frontend_agent.md`, `backend_agent.md`）を作成します。
   *※Impact Analysis Agentの分析に基づいて作成することを推奨*

4. **Gitリポジトリ初期化**:
   Manager Agentの指示に従い、Gitブランチ戦略を適用します。

---

## 📝 エージェント設計の黄金律

> **「安易にエージェントを増やすな」**

タスクが発生するたびにエージェントを新規作成（Phase X Agent等）すると、依存関係が複雑になり、待ち時間が増大します。
**Impact Analysis Agent** に「凝集度」と「結合度」を分析させ、可能な限り既存のドメインエージェントにタスクを割り当ててください。
