# GAWS: 納品・反映・レビュータイミング規定 (Draft)

※本ルールは将来的な適用を想定したドラフトであり、現在は「参照用」です。

## 1. 🔍 レビュー依頼のタイミング
エージェントは、以下のマイルストーンに到達した時点で **Reviewer Agent** にレビューを依頼しなければならない。

*   **設計完了時**: 実装を開始する前に、I/O定義や論理構造が要件を満たしているか。
*   **実装・単体テスト完了時**: 実際のコードが動いており、テストがPASSしているか。
*   **破壊的変更の直前**: 大規模なリファクタリングやDBスキーマ変更を行う前。

## 2. 🚀 Git反映（Delivery）のタイミング
**Manager Agent** は、以下の条件をすべて満たした場合にのみ、`main` ブランチへの反映を実施する。

1.  **Reviewer Agent** からの `APPROVED` 取得（必須）。
2.  **QA Agent** によるデプロイメントテストの合格（実装コードがある場合）。
3.  **Impact Analysis Agent** による「影響範囲外の破壊がないこと」の再確認。
4.  **スクリプト実行**: `scripts/gaws_checker.py` が成功を返すこと。

## 3. 🔄 例外的な即時反映ルール
以下の場合は、通常のレビュープロセスを簡略化して `main` への反映が許可される（要Manager承認）。

*   **ドキュメント・定数値の誤字修正**: ロジックに影響を与えないもの。
*   **開発環境の軽微な修正**: `.gitignore` や依存ライブラリのバージョン固定（マイナー）。

## 4. 🔏 ガードレールとの連携
本ルールは `scripts/gaws_checker.py` の検証ロジックと同期させ、機械的に反映の是非を判断することを目標とする。
