# Impact Analysis Report: T017b 実写データセット導入

**Task ID**: T017b  
**Subject**: 実写データセット導入による85%精度達成

## 📊 Analysis Summary
実写データセット（現実世界の顧客画像データ等）を導入し、解析精度を85%まで引き上げるタスクについて、現在のシステムへの影響を分析しました。本タスクは**「データ解析レイヤー」**の追加であり、既存の「管理システムレイヤー」との結合度は低く抑えることが可能です。

## 🔍 Impact Details

### 1. データモデルへの影響
- **影響度**: 🟡 Medium
- **詳細**: 実写データ解析結果（精度スコア、メタデータ）を `Customer` モデルに保存する必要があるか検討が必要。
- **対策**: `Customer` モデルをさらに拡張するのではなく、`analysis_results.csv` のような別ファイルを新設し、`customer_id` で紐づける構成を推奨。

### 2. インフラ・パフォーマンスへの影響
- **影響度**: 🔴 High
- **詳細**: 実写データの処理には計算リソースが必要。現状の Flask/CSV ベースの構成では、大量の画像・動画データの処理には不向き。
- **対策**: 非同期処理（Celery等）の導入、またはデータ解析部をマイクロサービスとして切り出し、API経由で結果のみを取得する構成を検討。

### 3. セキュリティへの影響
- **影響度**: 🔴 High
- **詳細**: 実写データ（特に顔写真等）は極めて機密性が高い。
- **対策**: 現状の `CryptoManager` による暗号化対象に、これらの解析元データも含める必要がある。ストレージの分離も検討。

## 🛠 Proposed Action Plan
1.  **Phase 8（データ解析基盤）の新設**: 現状の管理システム（Phase 1-7）とは切り離し、別モジュールとして実装を開始する。
2.  **APIベースの統合**: 管理システム側には「解析リクエスト送信」と「解析状況・結果の表示」機能のみを追加し、密結合を避ける。
3.  **プロトタイプ作成**: まずは `data/raw_samples/` ディレクトリを用いたオフライン解析から着手。

## 🏁 Recommendation
**GO (with architectural separation)**
既存システムの安定性を損なわないよう、疎結合な設計を維持したまま Phase 8 として着手することを推奨します。
