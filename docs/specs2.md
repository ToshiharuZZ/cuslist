# 顧客リスト管理システム(cuslist) 課金機能要件定義 (specs2.md)

## 1. システム目的
- 顧客管理システムに課金機能を追加し、利用者に応じた料金徴収を可能にする。  
- 利用者の利用形態に合わせた柔軟な課金バリエーションを提供。  
- CSVベースの管理方式を維持しつつ、課金情報も暗号化して保存。  

---

## 2. 課金バリエーション（料金モデル）

### 📌 サブスクリプション型
- 月額／年額課金  
- 利用者ごとに契約プランを設定（例：Basic / Standard / Premium）  
- プランごとに利用可能機能や顧客登録件数上限を制御  

### 📌 従量課金型
- 顧客登録件数や検索回数に応じて課金  
- 例：顧客100件ごとに追加料金発生  
- 利用者の操作ログを基に課金対象を算出  

### 📌 トランザクション課金型
- 特定操作（顧客登録・更新・削除）ごとに課金  
- 例：顧客登録1件につき¥10  

### 📌 ハイブリッド型
- 基本料金（サブスクリプション）＋従量課金の組み合わせ  
- 例：月額¥1,000＋顧客100件超過ごとに¥500  

---

## 3. 機能要件

### 🔐 利用者管理拡張
- 利用者情報CSVに「契約プラン」「課金方式」「残高／請求額」カラムを追加  
- 利用者ログイン時に契約プランを確認し、利用制限を適用  

### 💳 課金管理
- 課金対象操作の記録（顧客登録・検索・更新・削除）  
- 課金計算モジュールにより料金算出  
- 請求情報をCSVに保存（暗号化）  

### 📊 請求・支払い
- 請求書生成機能（CSVベース）  
- 支払いステータス管理（未払い／支払い済み）  
- 将来的に外部決済サービス連携を想定（Stripe, PayPalなど）  

---

## 4. CSVフォーマット仕様（追加）

### 利用者情報CSV (`users.csv`)
| カラム名       | 内容                          | 備考 |
|----------------|-------------------------------|------|
| user_id        | 利用者ID                      | ユニーク |
| password_hash  | パスワードハッシュ             | SHA-256 |
| role           | 権限                          | admin/user |
| plan           | 契約プラン                    | Basic/Standard/Premium |
| billing_type   | 課金方式                      | subscription/usage/transaction/hybrid |
| balance_enc    | 残高／請求額（暗号化）        | AES暗号化 |
| created_at     | 登録日時                      | ISO8601 |

### 請求情報CSV (`billing.csv`)
| カラム名       | 内容                          | 備考 |
|----------------|-------------------------------|------|
| billing_id     | 請求ID                        | ユニーク |
| user_id        | 利用者ID                      | 外部キー |
| operation      | 操作種別（登録/検索/更新/削除）| ログから取得 |
| amount         | 課金額                        | 暗号化保存 |
| status         | 支払いステータス              | 未払い/支払い済み |
| created_at     | 請求日時                      | ISO8601 |

---

## 5. 非機能要件
- **セキュリティ**：課金情報は暗号化保存、復号は認証済み利用者のみ  
- **拡張性**：将来的に外部決済サービス連携可能な設計  
- **可用性**：課金計算は操作ログに基づき再計算可能
