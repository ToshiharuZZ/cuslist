# GAWS 統治規定 (GAWS Governance Rules)

## 📖 目的
本ドキュメントは、Gemini Agentic Workflow System (GAWS) におけるエージェント間の役割分離を厳格化し、開発プロセスの透明性と品質を担保するための統治規定である。

---

## 🏗️ エージェント運用原則

### 1. Managerエージェントの専任化（兼務の禁止）
- **原則**: Managerエージェントは、プロジェクトの指揮・監督・検証に特化し、他エージェント（Backend, Frontend, Reviewer等）の実作業を**決して兼務してはならない**。
- **指示系**: 実装が必要な場合、Managerは適切な担当エージェントを「起動」し、具体的な作業指示（Assign）を下す。
- **技術介入の禁止**: Managerは `app/` 配下のアプリケーションコードを直接編集しない。コードの編集は担当エージェントに委ねる。

### 2. 作業フローの厳格化
- **エージェント起動**: Managerが作業対象エージェントを明示的に指定して起動する。
- **レポート作成の義務**: 全てのエージェントは、作業終了後に必ず詳細なレポート（`docs/reports/`）を作成し、Managerへ報告しなければならない。
- **Managerによる点検と検証**: Managerは次の工程（特にGit反映）に進む前に、以下の項目を必ず点検・検証する。
    - 担当エージェントのレポート内容
    - Reviewer Agent による `APPROVED` の有無
    - `python scripts/gaws_checker.py` による整合性確認

### 3. メタ認知的な切り替えの宣言
- エージェント（AI）が複数の役割を演じ分ける場合、各作業（Turn）の開始時に「現在どの役割（Agent）として振る舞っているか」を明示的に宣言し、役割に応じた制約を自らに課す。

---

## 🛡️ Git反映・環境操作のガードレール

### 反映の絶対条件
Managerは、以下のチェックリストが全て「完了」していない限り、`git commit` および `git push` を実行してはならない。

1. [ ] 担当エージェントによる実装および単体テスト完了報告
2. [ ] 担当エージェントによる `docs/reports/` への詳細レポート記述
3. [ ] Reviewer Agent による `docs/reports/` への `APPROVED` 記録
4. [ ] `python scripts/gaws_checker.py merge` の成功
5. [ ] Managerによる成果物の最終整合性確認

---

## 🔄 Managerエージェント起動ルーチン
Managerエージェントは、作業開始直後に必ず以下の手順を踏むこと。

1. **本規定の読み込み**: `docs/rules/gaws_governance_rules.md` を読み込み、現在のプロジェクト状況が本規定から逸脱していないか分析する。
2. **逸脱の検知と是正**: 承認のない実装や未作成のレポートがある場合、他の作業に優先してその是正（指示出し）を行う。
3. **継続的な自己監視**: 分離された役割を跨いでの「独断」が行われていないか、常にユーザーに対し透明性を確保した報告を行う。
